If the command-line tool won’t install

Installing the tool means making a link at /usr/local/bin/zephyr. The installer package makes it for you; a copy dragged out of a disk image takes one command in Terminal. These are the ways that goes wrong.

If you expected Zephyr to install it for you

The installer package does, while it runs, unless you cleared Command-Line Tool in its Customize pane. macOS keeps a running app out of /usr/local/bin, though, so a Zephyr that was dragged out of a disk image — or installed without that choice — can only show you the command and let you run it once yourself.

  1. In Zephyr’s settings, scroll to Command-Line Tool and click Copy.

  2. Paste the command into Terminal and press Return.

Zephyr doesn’t need to be running, and you only do this once per copy of the app. If the pane says Installed in /usr/local/bin and offers no command, there is nothing to do.

If Terminal won’t make the link

The command starts with sudo, which has two requirements.

  • It asks for a password. Type your login password — nothing appears as you type, which is normal — and press Return.

  • Your account has to be an administrator. A standard account can’t write there. Check in System Settings > Users & Groups, or ask whoever administers the Mac.

If Terminal says no such file or directory, the folder itself is missing. Run sudo mkdir -p /usr/local/bin first, then the command Zephyr showed you.

If Zephyr says the tool isn’t included

Two builds say this, for different reasons.

  • The App Store version. The App Store doesn’t allow an app to install anything onto your PATH, so it ships without the tool and the pane says so. The downloadable version is at riscfuture.github.io/Zephyr — see Choose between the two versions of Zephyr.

  • A build that simply doesn’t carry it. Download Zephyr again from the project’s site.

If the shell can’t find zephyr

The link is installed but your shell isn’t looking there.

  1. Open a new Terminal window. A shell already running never picks up a new command.

  2. Run echo $PATH and check that /usr/local/bin is in it.

  3. If it isn’t, add it in your shell’s startup file — ~/.zshrc for zsh.

Note: If you move Zephyr.app somewhere else, the link still points at where it used to be. Copy the command from Zephyr’s settings again and run it: it names the new location and replaces the old link.

If the tool can’t authenticate

zephyr keeps its credentials separately from the app, so an account the app linked is one the tool can list but not act as. Run zephyr auth link once for the tool. Exit 69 means no account is linked at all, which is how a script can tell that apart from a real failure.
